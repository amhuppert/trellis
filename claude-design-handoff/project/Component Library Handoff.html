01Stack & conventions

Read this before writing a single component. These rules are why the prototype shipped consistent and why the production library should too.

ConventionRule
LanguageTypeScript everywhere. Function components, named exports, typed props. No defaultProps.
StylingTailwind utility classes composed via cn() (clsx + tailwind-merge). Use cva() for any component with more than one shape. Inline style maps from the prototype must be ported to utility classes — they exist because the prototype is JSX-in-CDN, not because they're correct for production.
TokensReach for tokens via Tailwind classes (bg-surface, text-coral-ink) or CSS variables (var(--color-ink)) for inline SVG fills. Never a raw hex.
AccessibilityRadix UI primitives for hover-card, tabs, dialog, dropdown, tooltip. Wrap with Trellis styling; do not hand-roll behaviour the primitive already provides.
No dark: variants for colorSemantic tokens flip under .dark. Only use dark: for structurally different markup (rare).
Component contextNo engine component reads report-specific state directly. Anything report-shaped flows through providers wired by PageShell.
StorybookEvery exported component needs a Storybook story exercising each variant. CI fails without one.
Prototype-to-prod mapEach card below names the prototype file the behaviour came from. Use the prototype as the source of truth for behaviour; use this doc + the design-system spec as the source of truth for structure.

The reader's entire experience hangs off one shell. The shell owns five pieces of cross-view state, persists three of them to localStorage, exposes section/entity/synthesis/graph navigation helpers, and runs the global keyboard shortcuts. Every other component is a leaf of the shell.

  • focus chip (tab)Same open path as hover.
